# note-qa

**一句话**：把本地 markdown 笔记做成一个个人问答机器人 —— 提问、拿带引用来源的答案，再配一套能算出「它到底准不准」的评测脚本。全程跑本地 Ollama，**零 API key、零 Python 依赖**。


输出（**2026-10-08 复跑**，语料 `corpus/sample.md` = **7 块**，SHA256=`8B6F13B66C52BF81A3532BB5A61937D2950E4D058A3D34D04C91E9C27CF400F0`；留档 `留档-样例评测-修复后-2026-10-08.txt`）：

| 引用准确率 | **1/6（16.7%）**；至少引了一处 1/6 |

## 三条命令

前置：Ollama 在跑（`ollama serve`，或桌面版常驻），且有两个模型 —— `qwen14b:latest`（生成）+ `shaw/dmeta-embedding-zh`（中文向量）。

```bash
ollama pull shaw/dmeta-embedding-zh    # 408MB，首次要拉
ollama list                            # 确认上面两个都在

# ① 最小链路：读 md → 拼 prompt → 打印一行 JSON
python src/note_qa.py                                  # 换库：python src/note_qa.py --corpus <你的笔记.md>

# ② 检索：chunk → embed → top-k（问题列表写死在脚本里，换库时同步改）
python src/w2_retrieve.py                              # 换库：--corpus <你的笔记.md>

# ③ 评测：两把尺子（检索层 + 生成层）
python src/w3_eval.py
```

预期输出（①）：**一行合法 JSON**

```json
{"answer": "...", "sources": ["<md 文件名>"]}
```

首次调用要等模型加载进内存，30–60 秒属正常。三个脚本默认使用仓库内的 `corpus/sample.md`；W3 默认使用 `src/eval_set.sample.json`。

**不需要 venv、不需要 pip install**：三个脚本只用标准库 `urllib` 直连 `http://127.0.0.1:11434`。
（`requirements.txt` 里那行 `ollama>=0.4` 是「官方 SDK」的可选替代路线，不是跑通的前提。）

环境变量：无（全本地，不需要 API key）。将来接云端时加 `.env`（已在 `.gitignore` 里）。

`w3_eval.py` 的开关：

```bash
python src/w3_eval.py --no-gen          # 只跑检索层（约 10 秒）
python src/w3_eval.py --limit 3         # 只跑前 3 题（改代码后冒烟用）
python src/w3_eval.py | tee 留档-w3-YYYY-MM-DD.txt       # 留档（就用这条）
```

### 换成你自己的资料库

```bash
python src/w3_eval.py --corpus "path/to/你的笔记.md" --eval-set src/你的题集.json
```

- **语料**：单份 md，用 `## ` 标题分节（脚本按标题切块，再优先按行切；超长行在 `|。；，、;,.!?！？` 等边界附近切，上限 `MAX_CHARS=300`）。
- **题集**：格式抄 `src/eval_set.sample.json`。`answerable=true` 的题必须给 `gold_phrases`（**逐字**出现在语料里的原文），`answerable=false` 的题语料里必须真的没有答案 —— 出题前先 grep 一遍，这一步不能省。

## 已知边界

W1 最小链路 `note_qa.py` 只把笔记前 500 行塞进 prompt，没有检索。面对长文档，它曾**答错**（材料里有那句话，它挑了另一段）并把 `sources` 指向**一个并不存在的文件名**；这是 W1 的结构限制，也是 W2 加入检索的理由。该故障只在足够长的语料上出现，因此公开样例里看不到。

公开默认路径用 7 块样例语料，**复现不出该长文档故障**。2026-10-08 用修订前 W1 对 `corpus/sample.md` 发问原来的长文档问题，实际输出 `{"answer": "笔记中没有相关信息", "sources": []}`；原始输出见 `留档-W1样例对照-2026-10-08.txt`。默认问题现已换成样例问题。

## 评测说明

**评测集**：`src/eval_set.sample.json`（8 题，随仓库提供）
8 题 = **6 题"答案确实在样例语料里"** + **2 题"语料里根本没有"**（S07 / S08）。
`gold_phrases` 逐字出现在哪一块，那一块就是这题的"正确答案所在块"。出题前要 grep 原文，并在切块后再次确认每道有答案题至少有一个 gold 块；长段落可能被切开。无 gold 块时脚本标 NOGOLD 并以非零状态退出。

**两把尺子**（必须分开报，因为修法不同）

| 尺子 | 定义 | 影响它的层 |
|---|---|---|
| `recall@k` | gold 块是否落在检索 top-k | 块大小 / 向量模型 —— 只有检索层能修 |
| 引用准确率 | 答案正文里的 `[Source N]` 映射回块后，是否落在 gold 块 | 提示词契约 + 生成层；**字段说了不算，正则数得出来才算** |
| 拒答率 | 库外题里 answer 逐字等于"笔记中没有相关信息"的比例 | 幻觉对照，没有这一列数字再高也不说明问题 |

每个比例都配 **Wilson 95% 置信区间**（n=6/8 时点估计不可靠：`1/6` 的区间是 3.0%~56.4%）。

**关于更大规模评测集**：本仓库公开的是 8 题样例集。作者另在本机用一份 20 题私人题集（15 题有答案 + 5 题库外）跑过更大规模的对照实验，那份题集依赖不随仓库公开的私人语料，**因此不随仓库发布**，其历史数字也不在这里列出 —— 不同语料版本的表格彼此不可比。

> **报数字必须带语料版本/块数**：同一脚本换一份语料，所有数字都会变（实测撞过：同一份文档同一天出现 96 / 98 / 101 三个块数 = 三张表）。**这就是每条数字都要带语料版本的原因。**


**结论（一句话）**：这份公开样例上检索层 6/6 是**题目照着语料出的必然结果**，不能当成绩读；真正值得看的是生成层 —— **答得对 ≠ 可审计**：8 题里有 6 题的答案正文没有 `[Source N]` 标记、却照样填了 `sources` 字段。
在更大规模的私人题集上还观察到另外两类失败：**检索漏掉正确块导致的假拒答**（模型诚实地说了"没有相关信息"，错在检索层），以及**带引用标记的幻觉**（编数字、编地址、把两句时间缝成一句）。这两类的判层与第一刀见 `评测速查-现象到层到第一刀.md`。

## 脚本契约（`src/note_qa.py`）

最小链路须满足以下契约（当前脚本含命令行参数解析，45 行）：

1. 读一份本地 md 的**前 500 行**（默认 `corpus/sample.md`；可用 `--corpus` 或原有位置参数覆盖）
2. 拼 prompt：把原文和问题一起给模型
3. 调本地 Ollama，`format="json"`（把「模型自觉吐 JSON」换成「服务端保证」）
4. 打印**合法 JSON**，至少含 `answer`、`sources` 两个字段
5. 文件名固定 `src/note_qa.py` —— README 的「三条命令」就是照这个名字写的，改名要同步改 README

留档：真跑一次后把原始输出存成 `留档-YYYY-MM-DD.txt`（提交进仓库，供评测说明引用）。
